# 洞察骨架规范（Insight Spine v1）

> 任何洞察需求都走同一条骨架。差异由**任务包参数**表达，不由"范式类型"表达。
> 新需求来了不新增流程，只新增一份任务包。

## 0. 为什么不列范式清单

先列了"筛选排序 / 格局测绘 / 单标的评估 / 归因解释 / 监控追踪"，然后发现每来一个新需求就要补一条——那不是抽象，是待办列表。

把这几种需求拆开对比会发现骨架完全一样：

| 需求 | 对象集合从哪来 | 聚合成什么 |
|---|---|---|
| 新业务机会筛选 | 产业目录穷举 | 加权排序 |
| 某类工具的业界现状 | 穷举 + 过程中发现 | 特征矩阵 + 路线分组 |
| 该不该自研某能力 | 用户给定的几个选项 | 单一结论 |
| 某指标为什么下滑 | 候选解释假说 | 按证据支持度排序 |
| 季度跟踪竞对动态 | 上一批次的基线 | 与基线比对 |

中间的取证、核证、刻画、证伪、仲裁、成文**一模一样**。

**关键认识：差异是退化，不是缺失。** "单标的评估没有枚举阶段"是错的——它的枚举退化成了 n=1。"格局测绘没有排序"也是错的——它的聚合算子从排序换成了矩阵。

因此：

- **类型只有一个**（本骨架）。加类型要动架构，所以必须收敛。
- **预设可以有几十个**（`presets/`）。预设是常见参数组合的快捷方式，加一个只是加一份 JSON，加错了删掉即可。

先前文档里说的"范式"，一律理解为**预设**。

## 1. 十个动作

```
        ┌──────────────── 回边 R5：definition_drift（须人工，唯一能改 brief 的路径）
        │
        │   ┌──────────── 回边 R4：成文校验失败
        │   │
        │   │        ┌─── 回边 R1：取证发现新对象（走闸门后并入）
        │   │        │
        ▼   ▼        ▼
 ① 界定 ──▶ ② 枚举 ──▶ ③ 取证 ⇄ ④ 核证 ──▶ ⑤ 刻画 ──▶ ⑥ 聚合
   （含分诊）              ▲       ▲          ▲   │
                          │       │          │   │  R3：任一刻画 revision 变更
                          │       │          │   │      ⇒ 聚合标记 stale ⇒ 全量重算
                          └───────┴──────────┘   ▼
                          回边 R2：按质疑类型路由   ⑦ 证伪 ──▶ ⑧ 仲裁 ──▶ ⑨ 解读 ──▶ ⑩ 成文
                                     ▲                                          │
                                     └──────────────────────────────────────────┘
```

回边共 5 条，**全部指向更早的动作**，不存在向前跳跃。详见 §4。

| # | 动作 | 输入 | 输出 | 负责专家 |
|---|---|---|---|---|
| ① | **界定**（含**分诊**） | 自然语言需求 | `brief.json`（任务包）**或**「非洞察需求」拒绝结论 | 洞察规划专家 |
| ② | **枚举** | brief.subject | `subjects[]`（对象集合 + 来源定位） | 范围界定专家 |
| ③ | **取证** | subjects × dimensions | `evidence.jsonl`（证据卡） | 数据采集专家 |
| ④ | **核证** | evidence.jsonl | 更新 `verify_status` | 数据核证专家 |
| ⑤ | **刻画** | 证据 + dimensions | `characterization[]`（逐对象逐维度赋值） | 对比分析专家 + 领域分析专家 |
| ⑥ | **聚合** | characterization + aggregation | 结论结构（榜单/矩阵/分组/结论/变化清单） | 对比分析专家 |
| ⑦ | **证伪** | 聚合结论 + 证据（**不含刻画推理过程**） | `challenges` + 证伪备忘录 | 质疑审查专家 |
| ⑧ | **仲裁** | 结论 + 质疑 | `verdicts` | 争议仲裁专家 |
| ⑨ | **解读** | 仲裁后的结论 + 我方处境 | 启示（可直接借鉴 / 需验证再决策 / 明确不做） | 首席洞察专家 |
| ⑩ | **成文** | 终版结论 + 启示 | 报告（经发布闸）**+ 结构化基线快照** | 报告生成专家 |

全程由**洞察总调度**推进状态，它不做内容判断。

> `characterization` 取代了原先的 `scorecard`。评分卡只是刻画结果的一种（全 `ordinal` 维度时）。

## 2. 哪些动作可以退化，哪些永远不可以

**这是本规范最重要的一条。**

### 2.1 可退化的四个（前段）

| 动作 | 退化条件 | 退化后的行为 |
|---|---|---|
| ① 界定 | 需求已是结构化任务包 | 直接采纳，跳过翻译 |
| ② 枚举 | `subject.source.type = given` 或 `cardinality = 1` | 直接采纳给定清单，不做穷举扫描 |
| ⑤ 刻画 | `criteria.dimensions` 为空 | 退化为**事实摘录**：按证据整理事实，不做维度赋值（兜底档） |
| ⑥ 聚合 | 对象数 = 1 且算子 = `verdict` | 聚合即结论本身，无排序无矩阵 |

### 2.2 永不退化的六个（后段）

**③ 取证 · ④ 核证 · ⑦ 证伪 · ⑧ 仲裁 · ⑨ 解读 · ⑩ 成文**

这六个是方法论内核。任何洞察需求、任何深度档位、任何兜底情形，都必须完整执行。

- 没有取证与核证 → 产出的是模型记忆，不是洞察
- 没有证伪 → 产出的是确认偏误的放大器
- 没有仲裁 → 分歧会以"折中"的形式污染结论
- 没有解读 → 产出的是"什么是真的"，不是"这对我们意味着什么"，读者拿不走
- 没有成文闸 → 编造的数字会流到最终报告

**任何"为了快一点"而跳过后六个的档位设计，都是错的。** 快速档可以缩小取证广度、把证伪压到 1 轮、把返工预算调低，但不能取消任何一个动作。

### 2.3 退化必须显式暴露

任务包里发生的每一次退化，都要记进 `degradations[]`，并在报告首屏呈现：

> 本次洞察未做穷举枚举（对象集合由需求方给定），因此不保证覆盖完整。

这与"数据缺失必须显式暴露"是同一条原则：**降级必须可见。**

---

### 2.4 分诊：不是所有需求都该进这条骨架

**① 界定的第一个动作是分诊，且它有一个终止出口。**

洞察规划专家先判断三件事：

| 判断 | 不通过时的处置 |
|---|---|
| 这是**决策问题**还是**检索问题**？ | "帮我查 X 公司营收" → 直接检索作答，不启动专家团 |
| `decisionQuestion` 答得上来吗？ | 答不上来 → 退回澄清；连续两轮澄清仍答不上 → 判为非洞察需求 |
| 已有结论能否直接复用？ | 知识库里有未过期的同题结论 → 引用既有条目，不重跑 |

分诊拒绝是**正常终局**，不是失败。启动一次完整洞察的成本远高于一次检索，
把检索需求塞进这条骨架，既浪费预算又会产出一份过度包装的答案——**后者危害更大**。

拒绝时必须给出理由与替代路径，并记入台账（用于日后统计"多少需求其实不需要这个服务"）。

## 3. 闸门在哪里

闸门不是独立阶段，是**带触发时机的判据**：

| `evaluateAfter` | 时机 | 用于 |
|---|---|---|
| `enumerate` | 枚举之后、取证之前 | 零成本或低成本即可判定的排除条件。**尽量前置——闸门顺序错了成本差一个量级** |
| `characterize` | 刻画之后 | 依赖维度赋值才能判定的排除条件 |

闸门的 `action`：

- `reject` → 出局池（**全量留档**，下轮先复检，阈值调整或新证据出现都可能翻案）
- `defer` → 待补证池（本轮不参与聚合，保留）

**数据不可得一律用 `defer` 不用 `reject`。** 数据缺失是我们的信息问题，不是对象的质量问题；当成淘汰条件会让系统系统性偏向"公开数据充分"的成熟对象。

## 4. 对抗、返工与回环模型

### 4.1 对抗与仲裁的固定规则（与任务包无关）

- 证伪**最多 2 轮**。第 2 轮只能针对第 1 轮应答中的新证据。由编排层强制计数。
- 质疑审查专家**看不到刻画的推理过程**，只看结论与证据；模型与刻画者异源。
- 仲裁依据优先级：**证据等级 > 证据数量 > 逻辑一致性 > 保守优先**。
- **禁止投票、禁止取中值、禁止仲裁者自行补证。**
- 判不了就 `unresolved`，默认动作是**降置信度**并保留双方结论。

### 4.2 铁律：回环只回不进

**任何返工只能回到更早的动作，不能跳过中间步骤直接落到当前位置。**

补了新证据不能直接改分，必须重走 ④核证 → ⑤刻画 → ⑥聚合。

否则新证据会绕过核证进入评分——**那等于在防编造机制上开了一个后门**。
这条比本节其余所有规则都重要：它保证了"证据必须经核证"这个不变量在返工路径上依然成立。

### 4.3 回边 R2：质疑类型决定回到哪一步

不是所有质疑都能靠返工解决。**质疑类型就是路由键**：

| 质疑类型 | 根因 | 回退到 | 返工指令要点 |
|---|---|---|---|
| `evidence_missing` | 没取到 | ③ 取证 | 定向补采指定指标 |
| `evidence_weak` | 等级不够 | ③ 取证 | 找更高等级来源，不是更多同级来源 |
| `source_grade_too_low` | 用了 C/D 级 | ③ 取证 | 追到一手来源 |
| `stale_data` | 证据超龄 | ③ 取证 | 重新取当期数据 |
| `confirmation_bias` | 证据单边 | ③ 取证 | **补的是反向证据** |
| `scope_mismatch` | 数据在，口径用错 | ④ 核证 → ⑤ 刻画 | 先修证据卡的 scope，再重刻画 |
| `anchor_misapplied` | 证据够，档位判错 | ⑤ 刻画 | 不需补证 |
| `definition_drift` | 对象定义漂移 | ① 界定（**须人工**） | 见 4.6 |
| `counterexample` | 存在反例 | ⑧ 仲裁 | 判断问题，补证解决不了 |
| `causal_overreach` | 因果过度 | ⑧ 仲裁 | 同上 |

**`confirmation_bias` 这条有个坑**：它回到取证，但返工指令必须写明「补反向证据」。
不写清楚，采集专家会去找**更多同向材料**，反而加剧偏误——返工把问题放大了。

### 4.4 防止无限回环：预算 + 单调收敛

用**预算**约束，不用轮次约束（轮次挡不住"补证→重刻画→再质疑→再补证"的转圈）：

| 参数 | 建议值 | 含义 |
|---|---|---|
| `rework.perSubject` | 2 | 单个对象的返工次数上限 |
| `rework.globalShare` | 0.2 | 返工消耗占本批次总预算的比例上限 |

超预算 → 强制进 ⑧ 仲裁，按 4.1 的规则处置。

**单调收敛判据（关键）**：每次返工必须产出**新的 `evidence_id`**。
一轮返工后证据库没有新增条目 = 补证失败，该质疑按**保守优先**直接成立（降分 / 降置信度），不再重试。

没有这条，采集专家会反复去同一个查不到的地方查，一直转到预算耗尽。

### 4.5 回边 R3：局部修正必须触发全局重算

**聚合是全局操作，修正是局部的。** 改一个对象的一个维度分，`rank` 会重排整张榜。

机制：

1. 刻画结果带 `revision`；任一对象 `revision` 变化 → 聚合结果标记 `stale`
2. `stale` 的聚合结果**必须全量重算**（`rank` 全部重排、`matrix` 重出差异点、`cluster` 重分组）
3. 重算前的榜单**不得用于任何下游动作**——半新半旧的排序本身就是错的

**Top K 缓冲带**：证伪阶段做 **Top K + 3**，不是恰好 Top K。
重排后新进入 Top K 的对象大概率已经过证伪，避免二次回环。

仍有未证伪对象进入 Top K → **只对该对象补做证伪，不重开全局对抗**。
终止判据：Top K 集合连续两次重算不变 → 收敛。

> 缓冲带是拿一点冗余成本换掉一个会震荡的回环，比设计复杂的收敛逻辑实在【设计】。

### 4.6 回边 R5：唯一能改 brief 的路径

`definition_drift`（论证过程中对象定义悄悄变宽或变窄）是唯一可能需要改任务包的质疑。

但 brief 是**冻结**的——改了它，跨对象可比性就没了。所以：

- 这类质疑**升级为「口径异议」，必须走人工**
- 人工可选：驳回（判定定义未漂移）／ 澄清（补 boundary 说明，不改判据）／ **重开批次**（递增 brief 版本，整轮重跑）
- **不允许自动改 brief。**

### 4.7 回边 R1：取证过程中发现新对象

`subject.source.type` 支持 `discovered`——取证时发现了枚举阶段没覆盖到的对象（格局类洞察几乎必然发生）。

处置：新对象**并入候选池但必须走一遍闸门**，不能直接进入刻画。
并入后若已过 ⑤ 刻画阶段，则触发 R3 全局重算。

发现的对象要在报告中单独标注来源为 `discovered`——**它本身是枚举覆盖率不足的信号**，
下一轮应据此补充枚举目录。

### 4.8 回边全景

| 回边 | 从 | 到 | 触发 | 预算约束 |
|---|---|---|---|---|
| R1 | ③ 取证 | ② 枚举 | 发现新对象 | 计入 `globalShare` |
| R2 | ⑦ 证伪 | ③/④/⑤ | 按质疑类型路由 | `perSubject` + 单调收敛 |
| R3 | ⑤ 刻画 | ⑥ 聚合 | 任一 `revision` 变更 | 无（必须执行） |
| R4 | ⑩ 成文 | ③ 取证 | 发布闸数字校验失败 | 计入 `perSubject` |
| R5 | ⑦ 证伪 | ① 界定 | `definition_drift` | 须人工，不自动 |

**所有回边都指向更早的动作。** 骨架是有回边的 DAG，不是任意跳转的状态机——
这保证了任何一条执行路径上，"证据经过核证"与"结论经过证伪"两个不变量都成立。

## 5. 解读：从"什么是真的"到"这对我们意味着什么"

### 5.1 为什么它必须是独立动作

聚合产出的是榜单或矩阵——**那是"什么是真的"**。
决策者要的是**"所以我们该怎么办"**。这两者之间隔着一次独立的推理。

关键区别：**聚合只用对象的证据；解读还要用我们自己的处境**（能力、约束、战略、时间窗），
而这些信息根本不在证据库里。所以它不可能是聚合的副产品。

先前版本把解读的产出责任留空了——首席洞察专家只负责**验收**"这个结论有没有用"，
却没有任何动作负责**产出**它。结果是验收方会把一切都打回来，因为要验收的东西没人做。

### 5.2 解读的三分法

产出固定分三类（与仓库 `templates/insight.md` 的「对我们的启示」一致）：

| 类别 | 含义 |
|---|---|
| **可直接借鉴** | 证据充分、结论稳健、我方条件具备，可以直接动手 |
| **需验证再决策** | 结论成立但依赖未验证的前提，附上验证方式与判定标准 |
| **明确不做** | 结论清楚地指向"不该做"，写明理由——**这一类不可省略** |

"明确不做"最容易被略过，也最有价值：它把选项从决策桌上拿掉，节省的是后续所有人的时间。

### 5.3 解读的护栏（它是最容易冒出无证据断言的地方）

解读天然要越过证据边界，所以护栏要比别处更紧：

1. **每条启示必须标注【判断】**，并回指它依赖哪几条已仲裁的发现（`finding_ref`）。
2. **禁止引入新的事实性数字。** 需要新数字 → 走回边补证，不许在解读环节现编。
3. **禁止解读未经仲裁的结论。** 这就是为什么 ⑨ 解读排在 ⑧ 仲裁之后——
   对未经质疑的结论做解读，等于把偏误从事实层放大到决策层。
4. **措辞强度必须匹配置信度。** `low` 置信度的发现只能支撑"需验证再决策"，不能支撑"可直接借鉴"。

## 6. 基线快照：⑩ 成文的第二产物

`trend` 算子需要基线，但报告不是基线——报告是给人读的，基线是给机器比的。

所以 ⑩ 成文除报告外**必须同时产出结构化基线快照**：

```
<批次根>/baseline.json
  ├─ briefId + briefVersion     口径可比性的依据
  ├─ asOf                        时点
  ├─ subjects[]                  对象集合及其标识
  ├─ characterization[]          逐对象逐维度的终值（仲裁后）
  └─ evidenceIndex               每个终值对应的 evidence_id
```

规则：

- 基线**必须记录 brief 版本**。**跨 brief 版本的基线不可直接比对**——口径变了，差异无意义。
- 基线超过 `evidencePolicy.maxAgeMonths` → 不能直接用于 `trend`，须先重新核证。
- 基线是 `trend` 与下一轮"出局池复检"的共同输入。

## 7. 置信度（对所有聚合算子通用）

```
置信度 = f(证据覆盖率, 平均证据等级, 冲突数, 证伪推翻数, 证据超龄比例)

high   : 覆盖率 ≥80% 且 平均等级 ≥2.0 且 无未决冲突 且 核心结论未被推翻 且 无超龄证据
medium : 覆盖率 60–80%，或存在已仲裁的冲突
low    : 覆盖率 <60%，或存在未决的关键判定，或核心结论被推翻 ≥1 项
```

**排序类结论必须先按置信度分层，层内再排。** 高分 + 低置信度最可能的解释是"缺失数据被乐观填充"，不是"它真的好"。

## 8. 兜底档

当需求套不进任何参数组合（`dimensions` 为空、无可用算子）时：

- 刻画退化为事实摘录，聚合退化为 `verdict`
- **后六个动作照常执行**（含解读——兜底档同样要回答「所以呢」）
- 产出一份自由格式的、带完整证据链的分析

**能承认"我不认识这个需求的形状"并依然给出有质量的产出，才是真正的通用。** 没有兜底的通用是假通用。

---

## 9. 专家与动作的固定映射

专家对应**骨架的动作**，不对应"需求的类型"。因此：

**专家班底对所有洞察需求都是同一套，不随需求变化。**

用户不需要选专家——他不知道自己需不需要仲裁专家。真正需要选的只有两项：

1. 插哪个**领域包**（可为空）
2. 是否需要**合规审查专家**（产业机会类需要，工具类洞察通常不需要）

其余由骨架决定。用户的认知负担从"我需要哪些专家"（他不知道）变成"我要洞察什么"（他知道）。
