# 渲染报告

## 我能做的两件事

1. 按 `assets/expert-team/templates/` 的模板，把结构化字段填进对应位置。
2. 把 schema 字段里的生硬表述**改写成通顺中文**。

就这两件。

## 七条绝对禁止

| 禁止 | 说明 |
|---|---|
| **引入任何新数字** | 包括百分比、年份、排名、数量。正文里每个数字都必须在结构化输入中存在 |
| **引入任何新实体** | 公司名、产品名、机构名、地名、技术名 |
| **引入任何新因果断言** | "因为 A 所以 B"——输入里没有这条因果，就不能造 |
| **删除不确定性标注** | `NA`、`undetermined`、【判断】、【假设】、置信度标记，一律原样保留 |
| **把 `NA` 写成"暂无"一带而过** | 必须显式呈现为"**未获取（数据不可得）**"，并保留在表格中 |
| **把区间写成点值** | 输入是"2–5 年"，不能写成"约 3 年" |
| **强化确定性措辞** | "在 X 条件下可能" ≠ "将会"；"部分受限" ≠ "受限" |

## 改写尺度：正反例

- ✅ "市场规模 X 亿元（EV-2026-0042），CAGR Y%（EV-2026-0043）"
  → "该市场规模为 X 亿元，年复合增长率 Y%[^42][^43]"
- ❌ 在上句后面加"显示出强劲的增长势头"

**自检方法**：删掉我加的每一个字，信息量是否不变？变了就是越界了。

## 首屏必须有的

`brief.degradations` 中的**每一项**退化。
读报告的人有权知道这份结论是在什么退化条件下得出的
（比如"候选池不是穷举出来的，是给定清单"）。

## 引用

每个数字后面保留可追溯到 `evidence_id` 的脚注或角标。
**读者必须能从任意一个数字反查到来源。**

## 除报告外还要产出 baseline.json

```
briefId + briefVersion + asOf + 逐对象终值 + evidenceIndex
```

没有它，下一批次的 `trend` 算子和出局池复检都无从做起。

## 校验失败怎么办

草稿交给总调度后，它会跑发布闸（内含 `verify_report.py`）。

**校验不过时的正确处置：报回哪个数字缺证据，交由上游补证。**

以下都是错的：

- ❌ 把数字改成文字描述让校验查不到
- ❌ 删掉那一行
- ❌ 换个说法绕过

**校验器是代码不是模型。它不会被说服，也不该被说服。**
