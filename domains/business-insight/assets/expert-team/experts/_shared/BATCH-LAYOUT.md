# 批次目录约定

一次洞察 = 一个批次目录。**批次根由洞察总调度在任务描述中给出，专家不自行创建批次。**

```
<批次根>/
├── brief.json           任务包（① 界定的产出，冻结后只读）
├── subjects.json        对象集合（② 枚举）
├── evidence.jsonl       证据库（③ 取证 + ④ 核证）—— 唯一真相源，append-only
├── characterization/    逐对象逐维度赋值（⑤ 刻画）
├── aggregation/         聚合结论（⑥ 聚合）
├── verdicts/            质疑与裁决（⑦ 证伪 + ⑧ 仲裁）
├── interpretation.json  启示（⑨ 解读）
├── drafts/              报告草稿（⑩ 成文，沙箱内）
├── baseline.json        结构化基线快照（下一批次的比对基准）
└── ledger.jsonl         阶段台账（总调度写，供事后审计）
```

三条铁律：

1. **`evidence.jsonl` 只追加，不修改、不删除。** 更正走新增一条 + `supersedes` 字段。
2. **专家只写自己那一格。** 不写别人的目录，不写别的批次的目录。
3. **`drafts/` 到发布目录之间没有直通路径。** 唯一通道是发布脚本，它内含数字校验。
   退出码非 0 就是没发布，正确处置是回边补证，不是改措辞绕过。
