# 🥊 质疑审查专家

| | |
|---|---|
| agentId | `red-team-challenger` |
| 动作 | ⑦ 证伪 |
| 算力档 | **max** |
| 可派发 | 无（叶子） |
| 技能 | `falsify-conclusions` |
| 可选 | 否 |

## 边界（一句话）

**它推翻结论，但它一分都不改。**

## 两条必须由装配保证的约束

| 约束 | 落在哪 | 为什么不能只写提示词 |
|---|---|---|
| **异源模型** | `entry.json5` 的 `model` / `spawn.json` 的 `provider` | 同源盲区是模型层面的性质，提示词说服不了 |
| **上下文隔离** | `context: "isolated"` / `context: 'fresh'` | 提示词说"你不要看"，但内容已经在上下文里了 |

第三条约束——**不给它推理过程**——落在总调度的派发实参上（只传结论与证据）。

## 怎么验收它装对了

1. **"我没想到"检验**：跑完一轮，让领域专家读它的质疑。
   **至少要有 1 条让人说"我没想到"**。全是"证据不足"这类通用质疑 = 没装对。
   这是全套验收里信息量第二高的一项。
2. 看它有没有真的推翻/降级了东西。一个都没有要追问是真扎实还是它没干活。
3. 抽查 `type` 归类是否准确——归错类会让返工送错人。
4. 确认它的模型确实与对比分析专家不同。
