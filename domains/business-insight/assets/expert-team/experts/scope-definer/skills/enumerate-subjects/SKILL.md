# 枚举对象集合

## 可扫的目录来源（逐个扫完，留痕）

清单随领域变。下表是**产业机会类**洞察的默认来源，其他领域按同样思路替换：

| 来源类型 | 用途 |
|---|---|
| 国民经济行业分类 | 自顶向下的骨架，保证不漏大类 |
| 战略性新兴产业分类 | 政策口径下的新兴方向 |
| 五年规划及其专项规划文本 | 国家意图与重点方向 |
| 单体设备攻关 / 首台套类目录 | **装备层对象最密集的来源** |
| 行业协会的设备目录与产品分类 | 官方统计里没有的那一层颗粒度 |
| 海关税则章节（尤其机电类） | 从进口结构反推供给缺口 |
| 专利地图 | 技术分支与在位者布局 |
| 在位厂商产品线 | 竞品的产品目录本身就是一份清单 |

**工具类/软件类**洞察的等价来源：官方文档站的功能索引、包管理器的分类页、
基准测试榜单的参赛名单、行业报告的厂商象限图、开源仓库的 awesome-list、
主流集成平台的连接器目录。

原则不变：**每个对象要能指回某个目录的某一条。**

## 颗粒度判定

用一句话说清「**这是什么、给谁用、解决什么问题**」。

- ❌ 太粗："新能源装备"、"生物医药"、"AI 工具"
- ✅ 合适：某个具体工艺环节所用的某类设备/子系统；某个具体开发动作上的某类工具

说不清就继续往下拆。**拆到说得清为止，不要在中途停下来说"大概是这个层级"。**

## 提交前四问自检

1. 登记的每个来源目录**是否都扫完了**？未扫完的必须显式列出，不要沉默跳过。
2. 是否有候选**缺少 `enumerated_from`**？有则说明它来自联想——删除或补来源。
3. 是否有候选**停留在类目层**？有则继续拆。
4. **是否因为"我觉得不行"而漏掉了什么？** 回头补上。

第 4 问最重要，也最容易糊弄过去。诚实回答它：
回想扫目录的过程中，有没有哪一条你看了一眼就跳过了。那一条就是要补的。

## 退化的记法

`source.type = given` 或 `cardinality = 1` 时，枚举退化为直接采纳清单。
**退化必须记入 `brief.degradations`**，它会出现在最终报告首屏——
读报告的人有权知道"这份榜单的候选池不是穷举出来的"。
