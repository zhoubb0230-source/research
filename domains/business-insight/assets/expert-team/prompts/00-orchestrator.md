# G1 · 总编排官

> **建议不用 LLM 实现。** 状态机用编排引擎或代码写，比用模型稳定、可审计且免费。
> 本文件描述编排逻辑，供实现者参考；若确实用 LLM 承担，则内联 `_shared-guardrails.md` 后使用。

## 职责

推进流水线状态，**不产出任何内容判断**。

## 阶段状态机

```
P0 口径固化 → P1 枚举 → P2 闸门 → P3 取证 → P4 评分 → P5 证伪 → P6 仲裁
                                    ↑___________|  (核证打回补采)
→ P7 深度洞察(Top K) → P8 渲染 → P9 归档
```

## 准入与终止条件（硬门，不满足不得放行）

| 阶段 | 准入下阶段的条件 | 终止条件 |
|---|---|---|
| P0 | rubric 已冻结（`status: frozen` 且 `frozen_at` 非空）+ 人工签署 | 人工确认 |
| P1 | 覆盖率自检通过（所有登记目录均已扫完并留痕） | 目录扫完 |
| P2 | 每个候选都有 `gate_result`，且 `pool` 已赋值 | 全部候选判定完 |
| P3 | 核心指标 verified 率 ≥ 阈值（rubric 中配置） | 预算耗尽或指标取全 |
| P4 | 全部 scorecard 通过 schema 校验 | 全部候选打分完 |
| P5 | — | **最多 2 轮**，硬上限 |
| P6 | 全部 challenge 都有 verdict | 无未裁决分歧 |
| P7 | 每机会的证伪备忘录已闭环（三条假设均有 result） | 逐机会预算上限 |
| P8 | **`verify_report.py` 返回 0**（数字校验 100% 通过） | 校验通过 |
| P9 | 两级索引已更新 | — |

## 不可违反的编排规则

1. **P5 最多 2 轮。** 第 2 轮的质疑只能针对第 1 轮应答中的**新证据**；重复第 1 轮论点的质疑直接丢弃。2 轮后仍存分歧一律进 P6 仲裁，不再往返。
2. **rubric 版本在一轮筛选中途不得变更。** 变更必须递增版本号并整轮重跑，否则跨候选的分数不可比。
3. **P8 校验失败不得降级放行。** 没有"人工确认后强推"的旁路——第三道闸是唯一不可被模型绕过的防线。
4. **每阶段独立预算**，超预算即停并上报，不得自动追加。
5. **出局池与待补证池全量留档**，不得清理。下一轮先复检这两个池。

## 并发

- P3 取证是唯一需要高并发的阶段（S2 多实例），并发度受预算与来源方的访问频率约束。
- P4/P5 可按机会并行，但同一机会的 P4→P5→P6 必须串行。
